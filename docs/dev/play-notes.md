### Pathing reports (M8 A4)

A pathing report is what the lead saves while playing when a unit moves strangely; the replay tool explains it from the simulation's own decisions. Everything here is our own diagnostics (`// nocite: our own diagnostics`): no game rule changes, the save format stays 70 and the AI game format 31, and every golden is unchanged.

**The ring** (`crates/app/src/game/capture.rs`, `Ring`; held by `Play::capture`). The client keeps a few snapshots of the game, each its own save bytes (`Game::save`, which hold the brains and the whole replay). `Play::step_by` calls `Ring::after_tick` right after every tick, before any order of the next, so a snapshot is a tick boundary. The ring covers at least `WINDOW_MS` = 20 s of game time at the game's speed (`window_ticks(speed)`: 20 000 ms over `glasnost_ui::setup::period_ms(speed)`, rounded up; the session sets `Ring::speed` before each tick, so a network game uses the room's speed). A snapshot is taken every `spacing(speed)` = ⌈window / 2⌉ ticks, and the oldest is dropped once the next one already covers the window, so the oldest kept is one to one and a half windows old and the ring holds 2 or 3 snapshots (at most `MAX_SNAPSHOTS` = 6). Orders need no ring of their own: every person's order of a skirmish or of a network game goes through `Game::issue` into the game's replay, and the report takes those since its snapshot. The ring also keeps the last 8 battlefield clicks (tick, button, cell, object; `Play::click_map`) and up to 32 marks. A new game (and a rejoin's `Session::replace_game`) starts a new ring. Its cost, measured in the local lane (release build, a stock two-player map, game speed index 1, so a window of 1250 ticks and a snapshot every 625): a snapshot is about 1.1 MB and takes about 6 ms, against a mean tick of 1.2 ms, so the ring adds under 0.01 ms a tick on average and holds 3 snapshots, about 3.4 MB. A snapshot's few milliseconds fall on one tick in 625; we do not spread it.

**The keys** (`settings::Action::PathReport` and `Action::Mark`, labels "Save pathing report" and "Mark (pathing report)" on the settings screen, defaults P and M; neither is a command key of S-0213 claim 22). A settings file written before them that already gives P or M to a command keeps it, and the new action takes the first free letter or digit. *Mark* notes the present tick ("Marked tick N for the pathing report."). *Save pathing report* makes the bundle and stores it through `Client::save_path_report`, the same kind of function as the desync report's (`SaveReport`): natively `capture::save_file`, a file `path-reports/path-<capture tick>-<n>.gpath` under the working directory (a taken name gets `-2`, `-3` before the extension); in the browser the shell's download (`GameOptions.report`). The status line says "Pathing report of ticks A to B saved to PLACE.", or why not. `path-reports/`, `desync-reports/`, `*.gpath` and `*.gdsync` are git-ignored: a report holds a save of the game.

**The bundle** (`capture::Bundle`). The file is the magic `GPTH`, the format version (`capture::VERSION`, 1; little-endian u32), the SHA-256 of the body, then the postcard body: the build id (`capture::build_id()`: the client's build string with the save and game format versions), the rules hash, the map's content hash, the setup hash (`glasnost_net::start::setup_hash`), whether it is a network game, the snapshot (ticks run, tick number, bytes), every person's order since it (tick, house, order), the capture (ticks run, tick number, state hash), the marks inside the window, and what the person looked at (`Look`: house, selection in order, the view's origin and size and the cells under its corners, the cell under the pointer, the clicks, the game-speed index). A reader refuses, with a sentence for a person, a file too short for its header, another magic, another version, a checksum that does not match (damaged), contents that do not read, trailing bytes, and a capture before its snapshot. Bump the version whenever the layout changes.

**The trace** (`crates/deterministic/sim/src/trace.rs`). A read-only record of what the movement code decided: path computations (S-0212: mode asked and run, start, destination before and after substitution, congestion-marked cells, corridor, each cell search's expansions, recorded pairs, steps found and cost g as the bits of the simulation's own single-precision value, the result and the stored steps), what followed a failed computation, step checks that did not give clear (driving, walking and hovering: the cells, the entry outcome and the objects listed in the asked cell), blocked-step re-paths and whether the retry timer held them, give-ups, give-way requests and their answers, and group-destination spreading. It lives in `World::trace`, a `#[serde(skip)]` slot that is empty unless `trace::switch_on` fills it and that a clone of the world leaves empty; nothing in the simulation reads it. Recording copies values the movement code has in hand plus pure reads of the cell lists, so a traced run takes the same steps: `sim/tests/trace.rs` runs the determinism gate's scripted replay with and without it and compares the state hash after every tick, and checks that it recorded path computations and refused steps and is gone after a save and load. The only changes to the simulation crates are this module, the slot and the recording calls in `path.rs`, `drive.rs`, `walk.rs`, `hover.rs`, `scatter.rs` and `orders.rs`; `path::search` and `path::compute` gained untraced inner functions with the old bodies.

**The tool** (`crates/tools/src/path_report.rs`):

```sh
glasnost-headless path-report FILE [--out DIR] [--unit ID]... [--tick T] [--names] [--any-build]
```

It reads the report (exit 2 with the reason if it cannot), takes the rules and the tile catalogue from the synthetic fixture when the report's rules are its, else from the install in `GLASNOST_GAME_DIR` (the map found by its content hash, the rules checked against the report's hash), refuses a report of another build unless `--any-build`, loads the snapshot and checks its map, setup, tick and ticks run against the report, switches the trace on, and replays: at every tick the report's orders of that tick, then the tick, up to the capture, where it issues the capture tick's orders taken before the capture and compares the state hash. Exit 0 when it matches; 1 when it does not (the outputs are still written, headed "NOT reproduced"). The units of interest are the selected, those ordered in the window and any `--unit`, at most 32. Outputs go to `--out` or a folder named after the file next to it:

- `report.txt`: the build, game, window (ticks and orders), whether it reproduced, marks, selection, view, pointer cell and clicks; a summary of blockages (per unit, by what and by whom, with the ticks); then per unit its state at the snapshot and the capture, its track as runs of cells (`(x,y) ticks a-b`), a timeline (orders, path computations with the cells found or why none (a failed one names the destination asked for, since the trace has the searched-for cell only with a stored path), the cell searches' sizes and costs, whether the 5th failed cell search inside a corridor ended the computation (S-0212 claim 13's cap), and the likely reason of each re-path, refused steps with the objects in the way, where they stood and whether they were moving (a moving-blocker refusal whose cell lists no object names instead the vehicles whose vehicle-present flag is set on it at the end of the tick, S-0209 claim 1: for example both cells of a two-cell curve; pathing report 2), a run of identical refused steps on consecutive ticks as one line, blocked holds, waits, give-ups, give-way requests made and answered, group spreading, and changes of its behaviour, destination and locomotor state) and its totals. Units are named by id, kind, type index and house; `--names` adds type names (so a lane run's text holds no game data).
- `paths.png`: the cells around the tracks and paths, top down (x right, y down; the game's view turns this 45 degrees), 12 pixels a cell, at most 120 cells across, from the simulation's state at the capture only: passability category colours (lighter for higher ground), buildings, the other units, each unit of interest's track (thick), its searched paths (thin) and its place, crosses on the cells it was refused a step into, and a legend in the interface's own font.
- with `--tick T`, `state-T.txt`: every field of each unit of interest when the world reached tick T.

Tests (synthetic, CI): `crates/tools/tests/path_report.rs` plays the cramped fixture map with eight of the person's vehicles placed in the clearing, sends them all through its three-cell land bridge at once, marks and saves through the client model; the tool reproduces the capture hash, names a unit refused a step and the unit in its way, writes its outputs and the dump; damaged, truncated, foreign, other-build, other-rules and other-setup reports are refused with their reason, and a wrong capture hash reports "NOT reproduced". `the_ring_covers_the_window_and_a_failed_save_says_why` checks the coverage and the failure texts; `settings_tests` the keys' defaults and an older file's bindings, and `client_access_tests::the_mark_and_report_keys_save_a_pathing_report` presses M and P in a game and reads the saved bundle's mark, selection and capture hash.
