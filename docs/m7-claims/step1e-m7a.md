# M7a step 1e claim ledger (S-0613 revision 5)

This is part 5 of M7a step 1. S-0613 Gas clouds goes from revision 4, the one the code was built at (step 3.4), to revision 5 (commit 8e7134f, `git show 8e7134f -- spec/combat/S-0613-gas-clouds.md`). Every changed claim gets one class, as in [step1d-m7a.md](step1d-m7a.md):
- *satisfied*: already true, with the test that shows it;
- *changed*: code changed, with the test;
- *pointer*: the claim only points at another spec's claim;
- *not built*: with the reason (a claim for a part not built yet);
- *(c)*: editorial (front matter, scenario text, rewording, backing and confidence).

Per-spec ledger: [S-0613.md](S-0613.md).

| S-0613 gas clouds | 5 (from 4, 8e7134f) | Q-1240, Q-1241, Q-1242, Q-1244; Q-1243 stays open but is narrowed |

Requests:
- **Q-1240** (where the shared system enters play): claim 1. It is the last object of the game-start step to enter play, after the map-placed objects, the starting units and every tile or cell animation of loading, and before only the ore-twinkle animations. The interim (created before the map is read, first in the update order, object number 0) is retired. A particle requested while loading meets no shared system (new Edge case, a departure): its creation draws are taken and no particle is made.
- **Q-1241** (order within one particle's update): claim 18. The interim order (on even ticks drift, vertical speed and deflection; then damage, stage, lifetime) already satisfies it, so no code change. Only the citations changed.
- **Q-1242** (remaining lifetime): claim 5 and the new F9, E = (E_max + u) mod 65536. The interim (E = u) is retired.
- **Q-1243** (warhead systems of other kinds): still `open`, but claims 4 and 17 and the new Open question answer part of it. Every system takes a turn each tick, whatever its kind. Claim 17 covers lifetime and leaving play for every kind. A no-kind system holding particles never leaves play. Only how the smoke, fire, spark and railgun kinds treat their particles is still open. The interim is narrowed to match: such a system is now kept and takes its turns, and only its particle is not kept (its creation draws are taken). The workaround text in the request file is stale: it still says the system is not kept. Its file can only be changed by the lead, so it is not touched here.
- **Q-1244** (system lifetime and leaving play): new claim 17. The count-down runs after the kind's turn work for every kind, whatever the value, and a marked empty system leaves play in the same turn. The interim (count down only when positive) is retired.
- New requests: none (block Q-1152 to Q-1159 unused).

Object numbers: in a game whose rules give a shared gas system, the shared system used to take number 0. It now takes the number after the last object of loading. Map objects still start at 1. Every object created in play, particles included, now has a number one higher than before, which flips F8's stage-period parity for every particle. The gas claim tests do not depend on fixed numbers (`claim_15_stage_and_limit` reads the particle's own number). The gate's duel fixture gives a shared system, so its hashes moved (see below).

Save format: unchanged at 49 (no field added or removed; the values of `ParticleSystem::lifetime` now keep going down below −1). AI game format: unchanged at 18. Hashes: only `crates/sim-gate/golden/duel-m7a.txt` moved (the only gate fixture with particle systems); it was regenerated. Over seeds 1 to 16 the duel's gas minima are 32 clouds and 141 hits (were 16 and 26; the particles now live E_max + u ticks). The other minima moved too (see the gas section of [development.md](../development.md)). Every one is at least 3 except psychic sensor orders, which is 2 in every seed as before.
