# S-0607 r37, S-0306 r54: claim ledger, M8 step A3 intake 61

This intake takes in two spec revisions:

- **S-0607 revision 37** (magnetic lift): answers **Q-2160** (TELE against V3, intake 52b);
- **S-0306 revision 53** (projectiles): answers **Q-2157** (where the shells of the LTNK against
  ROBO stall land) and **Q-2158** (a hunter that makes a fire attempt every tick and no
  projectile), both from M-0005 (intake 52b). **Revision 54** follows it with one change, to
  claim 17 (a superweapon warp departure is not a loss of the target), and is taken in too.

Our engine built S-0607 r33 (intake 57) and S-0306 r45 (intake 51). Each diff from there to the
new revision was read in full (`git diff 298351f ab01d6c -- spec/combat/S-0607-magnetic-lift.md`,
`git diff ee49935 5f0c528 -- spec/combat/S-0306-projectiles.md` and
`git diff 5f0c528 1bf986f -- spec/combat/S-0306-projectiles.md`).

**Two new quirk switches**, both S-0306's, default on: `owned_shell_ground_pass` and
`switched_off_hover_lead` (judged for C7 below). **No new saved or hashed state**: the switches
are rules fields (in the rules hash, not the state hash), so save format 91 and AI game format 53
stay. No import row changes.

## What changed

### S-0607 claims 3 and 20 (r37, Q-2160)

*A hold starts only with a shot* (claim 3) and *a spawner while seized and after restoration*
(claim 20) state what our engine already did: the firing check's range test includes the minimum
range (S-0307 claim 9), the detonation makes no range test, a seize clears the slots through
`spawn::clear_slots` (S-0506 claim 13), the controller's passes go on while seized, and the
pending-target switch of S-0506 claim 25 keeps the pending target. No code changed; scenario L19
parts a to g are tested in `claims_s0607_r37.rs`.

### S-0306 r53 (Q-2157, Q-2158)

- **Terms, a projectile's firer.** A projectile has no firer when it was made without one, or
  when its firer was killed or removed from the game while it flies. A firer loaded into a closed
  transport is still the firer. Built as `combat::projectile::has_firer`: the projectile still
  carries its attacker (`death::mark_killed` and the delayed kill in `damage` clear it) and the
  firer object still exists. The cloak case (a firer that started to cloak since the shot counts as
  no firer, low) is not built: such a firer is still counted as the firer.
- **T1's first row** (`quirks.owned_shell_ground_pass`, on). Only the deck crossings detonate a
  projectile that has a firer. The terrain, the building band and the wall overlays apply only to
  one with no firer. The band now takes any house's eligible building, an open gate included,
  not an inactive laser-fence section and not a vehicle-like building; the wall overlays count only
  with no building in the cell; the band's point ends at the terrain height of the cell. Off: the
  whole row for every projectile, except that the firer itself and a building allied with the
  firer's house do not stop one with a firer. A projectile with a firer that passes below the
  ground flies on until another row (in open ground the deep-fall row, *h*′ ≤ −416) detonates it,
  at the surface (claim 20 a).
- **The proximity row** excludes the firer and its allies only while the projectile has a firer
  (`has_firer`; before, while the firer field was set, so a killed firer's allies were still
  excluded).
- **Claim 3 (b)** (`quirks.switched_off_hover_lead`, on). A hovering target is led while S-0503
  counts it as moving (a destination or a heading point, `hover::moving`), switched off or not.
  Before, a hover was led only by `occupancy::in_progress` (a heading point or a stored path), so a
  hover with a destination and neither of those was not led. Off: a switched-off hover is not led.
  Built as `projectile::led`, used by `launch` and `led_aim_point`.
- **A hover's speed estimate** (claim 3 and its Open question: a hovering vehicle's speed
  fraction is S-0503's). `drive::speed_estimate` read the speed fraction from the drive state,
  which a hover does not use, so a hover's *u* was 0 and no hover was ever led, switched off or
  not. It now takes the hover's own ρ (S-0503 claim 4, `hover::speed_fraction`).
- **Claim 6 (a).** A void launch in a vehicle's firing step leaves the rearm countdown unchanged,
  and the firer attempts again on each later *can fire*. Already so (`fire::shot` returns before
  the countdown); now tested through the tick.
- **Claim 5** (the fire point unraised for the direction): already built at intake 51.

### S-0306 r54

Claim 17: the departure of a superweapon warp member is not a loss of the target, so a projectile
flying at it keeps it as its target object. This is S-0513 claim 39's rule (r43), which intake 60
built in `superweapons::warp::depart` (no `teleport::targeters_drop` at the departure), merged
before this intake's rebase. Nothing more to build here: see the claim table.

### Tests of other specs that moved

- `claims_s0302::claim_16_firer_in_a_countdown`: the tower's old shot, which has no firer once the
  tower is killed at the delayed-kill hit, detonated in the tower's own building band (T1's first
  row now takes any house's building) and finished the tower. The test now lets the shot leave the
  tower's cells before the hit; its claim is unchanged.
- `claims_s0405_r47_hover::claim_20_a_disabled_hover_is_targeted_damaged_and_destroyed`: the
  disabled hover keeps a heading point, so S-0503 counts it as moving and claim 3 (b) leads it,
  and the hunter's shots no longer reach it in the test's 2000 ticks (the P44 mechanism). S-0306's
  *Changes for other specs* says claim 20 stays true (the lead reads the moving state, not the
  disabled state). The test now runs with `switched_off_hover_lead` off; a second test,
  `claim_20_a_disabled_hover_is_targeted_with_the_lead_quirk_on`, keeps the targeting part with the
  switch on.

## C7: the two switches judged

| Switch | Spec | Verdict | Reason |
|---|---|---|---|
| `switched_off_hover_lead` | S-0306 claim 3 (b), Edge cases | admitted (off) | (1) The Edge case states the off position (a switched-off vehicle is not led; the aim point is its reference point), built in `projectile::led`. (2) The quirk text states a stuck attacker: "Attackers that keep it as their target can then fail to destroy it for the rest of the game" (the ROBO stall of M-0005, Q-2157 and Q-2158). (3) It acts only on a switched-off hovering target, a vehicle that does not travel and does not fire; the off position aims at where it is, so it changes no balance between working units. Test: `layers::tests::play_fixes_sets_only_the_admitted_switches_off`; the two positions: `claim3b_switched_off_hover_lead`. |
| `owned_shell_ground_pass` | S-0306 T1, Edge cases | rejected | Condition 3: the off position detonates every straight or arcing shot that passes below the terrain or through a building band or wall overlay, which changes hits of every artillery and cannon shot in the game (a broad combat change). Condition 2: the quirk text states shells that fly on below the ground, and the stuck attacker it can give is the hover lead's, which the admitted switch answers. |
