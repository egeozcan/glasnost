# S-0215 claim 16: the no-threat fall-back on damage (M8 seam)

Brief: `.claude/worktrees/M8-SEAM-S0215C16-BRIEF.md`. Spec: S-0215 r104, claim 16 (*No-threat*),
with claims 1, 10, 13 to 15, 17, 18 and 39, and S-0607 claim 9.

Seam sweep 5a (`seams-5a.md`, row intake57:185) found that we had built only the first half of
claim 16, the search exclusion (`combat::acquire`). The second half was missing: "When a mobile
actor that is not a team member, with the no-threat property but not the zombie property, takes
damage from a known attacker and survives, it falls back to rest at once (claims 13 to 15), which
normally ends the no-threat behaviour." Intake 74 built r104 without that half.

**Result.** The fall-back is built as `process::no_threat_fall_back`. It is called from
`combat::damage::reactions` for a hit that lowers health, leaves the actor alive and has a known
attacker. There is no quirk switch, so no C7 verdict is owed. No hashed state was added, so
there is no format bump: save 99 and AI game 62, as on main after intake 96. Request filed: **Q-2586**, on the
fall-back's order against the hit's other reactions and on whether a heal triggers it. The
interim rule is below.

## Where it sits among the damage responses

A hit's responses, in our order (`damage::apply`):

1. The hit's own S-0302 effects: health, the damage stage, death.
2. Anger: S-0309 claim 16.
3. Fear: S-0107 claim 16, infantry only.
4. **The no-threat fall-back: claim 16.**
5. Retaliation: S-0215 claim 18, S-0309 claim 18.
6. The crush response: claim 39, a vehicle only.

The spec fixes only the last place: claim 39's crush response "follows every other effect of the
same hit on the vehicle", so the fall-back comes before it. No claim gives its order against
retaliation, the scatter from damage, fear or anger, and the order changes the outcome. That is
**Q-2586**.

The interim rule:

- The fall-back comes after anger and fear and before retaliation.
- It is judged on the behaviour current when the hit lands, as the claim reads: "with the
  no-threat property ... takes damage".
- Retaliation then judges the state the fall-back leaves, by its own rules. In claim 18's terms,
  an actor that retaliates gets *attack* as an override (claim 10). With
  `quirks.override_suspends_queued` on, the rest behaviour the fall-back queued is put aside but
  stays queued.
- The scatter from damage (claim 19, S-0208 claim 15) is not built in our hit reactions, so
  Q-2586's scatter question has no effect yet.

## The install's no-threat behaviours

The local-only lane `crates/tools/tests/no_threat_lane.rs` (`--ignored`, with
`GLASNOST_GAME_DIR`) lists the behaviours whose resolved properties include no-threat. The
values stay on the terminal and are not recorded here. The lane found two behaviours:

- One that only a building can hold. The mobile test excludes it.
- One that our engine's own code enters only from a map's placement record (S-0009 claim 41,
  `objects::place_map_objects`). A behaviour order (`Order::Behaviour`) naming it would also
  set it, but neither the AI nor the client issues one; the AI, UI and app sources do not name
  it.

So in our lanes the fall-back can be reached only by a map-placed mobile object that starts in
that behaviour and is then damaged. The arena places its own units, and the sweeps use synthetic maps, so
neither reaches it. In the AI quick lane, a skirmish map's pre-placed objects could, if a map
places one in that behaviour and it is shot. The lane results below show whether any game
diverged.
