# Contributing

Read [PROVENANCE.md](PROVENANCE.md) first. It says what you may read and how behaviour knowledge enters this repository. These rules apply to AI implementer sessions and to any future human contributor.

## Workflow

1. **Pick a spec.** Choose an approved spec in `spec/` (`status: approved`) or an open issue that cites one. Engine behaviour is implemented only from approved specs and measurement records.
2. **Read it and its measurements.** If anything you need is missing, ambiguous or contradicts another spec, stop and write a spec request in `spec/requests/` ([how](spec/requests/README.md)). Do not fill the gap from memory or by guessing.
3. **Implement.** Put each behavioural constant, formula, ordering rule and quirk switch next to its citation:

   ```rust
   // spec: S-0042
   const RELOAD_RESETS_ON_MOVE: bool = true;
   ```

   Values that come from the user's imported rules are read from the imported data, never written into code. Only engine defaults (what applies when a key is absent) live in code, and each one cites a spec.
4. **Test.** Add tests that cite the same IDs:
   - unit and property tests on synthetic data;
   - a determinism check for anything that touches simulation state (save/load round trip, identical state hash across runs);
   - where a measurement exists, a test that asserts the *relation* the measurement confirms, with its tolerance. If the value itself is local-only, the test goes in the local lane.
5. **Open a change** with a description that lists the S-, M- and Q-IDs it touches.

Engine design decisions of our own (crate layout, rules format, renderer) need no spec. Behaviour that is meant to match the original always does.

## Determinism rules (simulation crates)

The simulation must give bit-identical results on every platform (wasm32, x86-64, aarch64) for lockstep multiplayer, replays and save games.

- **No floating point** in simulation state or logic. Use integers and fixed point. Clippy lints enforce this. The only exception is a narrow wrapper type allowed site by site when a spec requires it; it permits only `+ − × ÷` and `sqrt`, with no transcendental functions, no fused multiply-add and no relaxed SIMD.
- **Never parse simulation numbers through `f64`.** Rules and imported values are parsed straight into integer or fixed-point types.
- **No `HashMap`/`HashSet` iteration** in the simulation. Use `BTreeMap`, sorted `Vec`s or index maps with a defined order. Iteration order must never depend on hashing, addresses or allocation.
- **No wall-clock time, threads, async, I/O or host calls** in the simulation. Time is the tick counter.
- **One simulation RNG**, seeded from the match setup and part of the saved state. Visual effects use a separate cosmetic RNG that the simulation never reads.
- **Fixed tick pipeline.** Each tick runs its phases in one documented order. Components never pick their own order or run outside their phase.
- **Stable IDs.** Objects get IDs from a deterministic counter, never from pointers.
- **Everything is serializable.** All simulation state saves and loads in a versioned format, and the state hash is identical after a round trip.
- **Rendering, audio and UI only read** simulation state. Player and AI input reaches the simulation only as orders queued for a tick.

## No EA bytes, anywhere

This repository never contains EA data: not in source, tests, fixtures, CI caches, release artifacts, screenshots, logs or issue attachments.

- No game files or parts of them (archives, sprites, voxels, palettes, sounds, maps, string tables, rules files).
- No stock rules values, whether copied by hand or converted.
- **Tests and CI use synthetic data only**: a synthetic ruleset and fixtures generated by our own writers, either at test time or committed under `tests/fixtures/` as our own work.
- **Local-only lane.** Tests that need a real install (importer coverage, fidelity checks against imported values, local-only measurement values) are gated behind an opt-in feature or environment variable. They never run in CI, and their inputs and outputs are git-ignored.
- Logs and crash reports never include asset content or install paths.
- Fallback art, placeholder UI and anything else we ship must be our own and visibly original.

## Dependencies

Dependencies must be compatible with GPL-3.0-or-later: MIT, Apache-2.0, BSD, Zlib, MPL-2.0, LGPL or GPL-3. Code adapted from OpenRA or XCC (GPL-3) keeps its copyright notice and states its origin in the file header and the commit message.

## Commits

- **DCO sign-off.** Every commit carries a `Signed-off-by:` line (`git commit -s`), certifying the [Developer Certificate of Origin](https://developercertificate.org/).
- **Style:** a short summary line in the imperative, prefixed with the area: `sim: apply damage before removal in mutual kills (S-0042)`. Common prefixes: `sim`, `rules`, `import`, `render`, `ui`, `ai`, `net`, `ci`, `docs`, and `spec` / `measure` for spec and measurement files.
- Put the S-, M- and Q-IDs a commit implements in the summary or the body.
- AI-assisted commits keep the tool's attribution trailer, and the human who reviewed and accepted the change signs off.
- One logical change per commit. Specs and measurement records are committed separately from code.
